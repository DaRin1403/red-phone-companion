# B 路线实施方案：完整双向语音终端

> 目标：**你打电话跟我说话，我也从听筒里回你。**
> 参考实现：`源码\codex-redline\`（prikevs，MIT）——已完整跑通，但绑死 macOS + Codex + OpenAI 云端。
> 本项目：移植到 **Windows + DSH + 全本地语音**。
> 立项：2026-09-04

---

## 一、最终交互剧本（这就是"完整版"的样子）

| 你的动作 | 系统行为 | 听筒里听到 |
|---|---|---|
| 提起听筒 | HT802 摘机自动拨号 → 本机 SIP 服务接通 | 660Hz 就绪音（300ms） |
| 说话 | 实时流式录音 → 本地 ASR | （静音） |
| **放下听筒** | 判定提交 → 文字注入 DSH 输入框并发送给我 | 挂断 |
| 我处理完 | **电话响铃**（最多 2 声） | 铃—— |
| 你接听 | 播报我的回复 | 先 1 秒静音，再念回复 |
| 回复念完 | 播就绪音，**自动进入下一轮监听** | 660Hz 就绪音 → 可直接接着说 |
| 播报中挂机 | 立即停止，跳过这条回复 | 挂断 |

**与 P0 方案的本质区别**：电话从"麦克风+耳机"升级成**完整终端** —— 有真拨号音、真振铃、能主动呼你。

## 三、技术选型定版

| 模块 | 选型 | 理由 |
|---|---|---|
| **ATA 网关** | **Grandstream HT802** | 参考项目已验证；双口 FXS；有 Off Hook Auto Dial 与可配铃流 |
| **网络** | 本机已有的 **ASIX USB 千兆网卡** | ✅ 已具备，无需购买 |
| **SIP/RTP** | 复用参考项目的 `phone-sip.mjs` 思路（Node 自实现） | G.711 PCMU / 8kHz / 20ms 帧，最简可用 |
| **本地 ASR** | **已跑通的 CapsWriter + SenseVoice** | 复用 P0 成果，实测时延 0.13–0.38s |
| **本地 TTS** | **Qwen3-TTS 0.6B**（首选，流式首字 97ms）<br>**CosyVoice2 0.5B**（备选，工程最成熟） | 均为 Apache 2.0、可本地、中文原生；0.6B 仅占 ~2GB 显存，不挤占 ASR |
| **文字注入** | 复用 CapsWriter（模拟键盘 / 剪贴板兜底） | P0 已验证 |
| **回复通知** | ⚠️ **本项目最关键的待攻关点**，见 §五 | DSH 没有现成的 Stop Hook |
| **就绪/错误音** | 自生成正弦波（660Hz 300ms / 220Hz 600ms） | 参考项目验证过的参数 |

**为什么 TTS 选流式**：电话场景对延迟极敏感。Qwen3-TTS 支持"边生成边播放"，第一句 97ms 就能出声；
CosyVoice2 首包约 1.5s。**先上 Qwen3-TTS，代码里做成可切换**，两者都装了对比。

## 五、⚠️ 最关键的待攻关点：怎么知道"我回复完了"

参考项目靠 Codex 的 `Stop` Hook。**DSH 没有等价的官方 Hook**，所以这一环要自己解决。

**目标**：我在 DSH 里生成完一条回复 → Companion 收到通知 → 给你响铃。

**候选方案（按可靠性排序）**：

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **① 轮询会话文件** | 监听 `~/.dsh/sessions/.../<session>.jsonl` 的修改，检出新的 assistant 消息 | 无需改 DSH，纯外部 | 需区分"你在打字"和"电话触发的回合"；可能需要标记机制 |
| **② 轻量 HTTP 回调** | Companion 起一个小 HTTP 端口，我调用一个工具/命令通知它 | 最可控 | 需要我能主动触发（我可以做到） |
| ③ Cordis 动态插件 | 挂到 DSH 事件上 | 最优雅 | 动态插件重启即失效，不适合常驻 |

**倾向方案 ①+② 组合**：
- 电话提交的输入打上标记（比如把注入的文字前缀一个不可见标识 / 或记录提交时间戳）
- Companion 只对"由电话发起的回合"的完成事件响铃 → 避免你键盘打字时被电话打扰
- 方案 ② 作为兜底与调试通道

## 六、分阶段实施计划

| 阶段 | 内容 | 可验证产出 | 依赖 |
|---|---|---|---|
| **S1** | 建项目骨架：SIP/RTP 模块移植到 Node（Windows 可跑） | 能起服务、能收 SIP 请求（用软件模拟器测） | 无（可先做） |
| **S2** | 音频链路：μ-law 编解码 + 就绪音/错误音生成 | 生成 wav 与参考项目对比一致 | 无 |
| **S3** | 本地 TTS 接入 + 电话编解码转换 | 输入文字 → 输出 8kHz PCMU 流 | 无（可先做） |
| **S4** | ASR 接入（复用 CapsWriter 的 SenseVoice） | 电话音频 → 文字 | 无（可先做） |
| **S5** | 回复完成通知（§五方案落地） | 我在 DSH 回完 → Companion 收到事件 | 无（可先做） |
| **S6** | **硬件到货：HT802 配置** | `inspect` 读到设备、摘机自动拨号成功 | ⬅ 需到货 |
| **S7** | 联调：摘机→说话→挂机→提交 | DSH 输入框出现文字 | ⬅ 需到货 |
| **S8** | 反向：回复→响铃→接听→播报 | 完整闭环 | ⬅ 需到货 |
| **S9** | 打磨：VAD 断句、多轮连续、挂机打断 | 体验顺畅 | ⬅ 需到货 |

**关键：S1–S5 全部可以现在做，不依赖硬件。** 硬件到货只剩配置与联调。
